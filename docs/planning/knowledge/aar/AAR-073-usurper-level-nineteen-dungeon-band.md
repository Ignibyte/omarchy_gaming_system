## What happened

- Implemented external rules/state/cartridge v24 with exact Level 19 records
  180–189, draw-free switching across levels 1–19, preserved rejection draws,
  strength 23/defence 11/69 HP encounters, retreat behavior, bounded
  `option_s`, one fixed provider action, signed presentation, fixtures,
  provenance, compatibility documentation, and full tests.
- Ratcheted the trusted-QML largest-plan regression from twenty-one to
  twenty-two current controls. It now proves recursive delegate cardinality,
  stale removal, positive non-overlapping geometry, dynamic enablement, and
  exactly one action from both a surface-level pointer click and a real Return
  event for every current control.
- The user's live duplicate/inert report was treated as release-blocking. The
  old v23 process had unique provider declarations, and the settled QML
  surface could not reproduce duplication. That process tree and private run
  root were removed and replaced with the only fresh v24 Usurper window on
  workspace 8; workspace 1 remained active. Desktop lock state prevented a
  compositor screenshot, so visual confirmation is not falsely claimed.
- External validation passed 130 Rust tests, strict lint/docs, authenticated
  source/provenance, six QML cases, seventeen signed screens, local play, and
  the complete provider restart corpus. Codex Security closed all seventeen
  frozen review items with zero plausible or reportable findings.
- The isolated platform diff gate passed all twenty-four stages both before
  and after OpenWiki finalization. Final validation and completion receipts
  match gated state
  `67d8958eeb72a2681038009693fd8c36a046118b329f30f8aaa27c6a61a949a1`.

## Failures captured

- No new `BF-*`: the live duplicate appearance did not reproduce in the fresh
  settled surface, so no unsupported root-cause label was minted. Provider
  data duplication was disproved; stale preview/process lifecycle remains the
  only observed discrepancy.
- No new security ID: the scan retained the known same-developer,
  loopback-only render-generation lifecycle debt and found no new Level 19
  attack path. TAC advisory status could not be checked because its connector
  was unavailable.
- No new `BF-*`: the first isolated receipt wrapper ran as namespace UID 0, so
  `makepkg` correctly rejected stage 16. The stopped run's disposable
  resources were removed; a split UID mapping configured networking as
  namespace root and ran the gate as mapped UID 1000, after which all stages
  passed.

## Prevention rules captured

No new durable ID was warranted. Existing rules correctly forced the important
behavior: replace preview processes between cartridge builds; require unique
provider declarations; and prove recursive cardinality, stale removal,
non-overlap, enabled propagation, surface hit-testing, and keyboard
exactly-once activation at the largest current plan.

## Architecture decisions

No new ADR was required. ADR-0002's authority boundary held: the separate
provider owns Usurper data, rules, state, RNG, and revisions, while OmarchyGS
adds only game-neutral regression evidence. `option_s` is bounded inert view
data. The 256-draw trace remains inside the provider envelope at Level 19,
with its roughly four-per-million exhaustion risk explicit; deeper levels
still require compact trace work before the valid tail narrows further.

## Effectiveness

Effective. Every recalled rule influenced source selection, rejection traces,
provider transitions, signed action uniqueness, state sizing, or live-control
evidence. Treating the user's duplicate/inert report as release-blocking
strengthened the regression from object-level checks to surface-level pointer
hit-testing for all twenty-two controls. Full external, security, restart,
OpenWiki, and isolated platform-gate evidence pass without committing,
publishing, deploying, or admitting the development cartridge.
