## What happened

- Implemented external Usurper rules/state/cartridge v23 with exact Level 18
  records 170–179, draw-free switching across levels 1–18, preserved
  `Random(180)` rejection work, strength 22/defence 11/66 HP encounters,
  Level 18 retreat behavior, bounded `option_r`, one fixed provider action,
  signed presentation, fixtures, provenance, compatibility docs, and tests.
- Ratcheted the platform's trusted-QML regression from twenty to twenty-one
  current controls. A live duplicate-control report exposed implicit Loader
  row geometry, so each heterogeneous delegate now derives its row height from
  the loaded trusted node; the test rejects zero-height or overlapping rows and
  activates all 21 controls once through real Return events.
- Full external validation passed 124 Rust tests, strict lint/docs,
  authenticated source/provenance, six QML cases, seventeen signed screens,
  and provider-backed local play. The platform renderer suite and complete
  isolated diff gate also passed; the final gated-state receipt is
  `84d45886eafd6815d64614fd84edf31a34ca93c171743585a4b2c39028e6aca5`.
- Real compositor input on workspace 8 advanced a fresh v23 session into Level
  18 with one revision per accepted action. The refreshed window remains open
  for user inspection while workspace 1 remains active.
- Codex Security scan `5670926d-67b1-41ec-9260-baf28c327095` closed all 17
  review items with zero reportable findings. The reproduced render-generation
  retention growth is development-only lifecycle debt requiring hard caps
  before any lower-authority, remote, shared, multi-user, or long-lived reuse.

## Failures captured

- `BF-omarchy-gaming-system-implicit-qml-loader-row-overlap-001`: the trusted
  surface's heterogeneous Repeater used Loader delegates with no explicit row
  height while their items instantiated asynchronously. Settled object counts
  remained correct, but live replacement could temporarily stack controls.
- `BF-omarchy-gaming-system-test-database-port-collision-001`: the first diff
  gate could not bind its compose PostgreSQL fixture because the enabled system
  PostgreSQL already owned `127.0.0.1:5432`; stages reaching that unrelated
  cluster found no test role. The unchanged gate passed through an isolated
  network namespace and port-forwarded test database without stopping the
  system service.
- No new security ID: repeated development-only render generations retain
  bounded files until process exit. Current loopback capability, private run
  root, wrapper cleanup, and same-developer authority make this self-impact,
  but shared or long-lived reuse must add generation/count/byte eviction caps.
- No new ID: the first post-archive isolated wrapper omitted its offline and
  compose-project environment, so two package stages attempted unreachable
  registry access and later database scripts selected the default project. The
  run was stopped, its disposable resources were removed, and the corrected
  exact environment passed all 24 stages.

## Prevention rules captured

`PR-omarchy-gaming-system-bind-loader-row-to-loaded-item-geometry-001`:
heterogeneous asynchronous QML delegates in a positional layout must bind the
delegate row to the loaded item's positive geometry and prove non-overlap after
realistic plan replacement.

`PR-omarchy-gaming-system-preflight-fixture-port-and-identity-001`: before a
receipt gate starts an integration database, prove the required listener is
available and that any reachable database is the intended disposable fixture;
otherwise isolate the fixture without altering unrelated host services.

## Architecture decisions

No new ADR was required. ADR-0002's authority boundary held: the separate
provider owns Usurper rules, data, state, RNG, and revisions; OmarchyGS changes
only game-neutral trusted presentation geometry. `option_r` is bounded inert
view data. The 256-draw trace remains within the provider envelope, while the
reproduced development render-generation growth remains an explicit lifecycle
constraint rather than production-ready behavior.
