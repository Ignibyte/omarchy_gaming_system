## What happened

- Implemented external Usurper rules/state/cartridge v20 with exact Level 15
  records 140–149, draw-free levels 1–15 switching, forced rejection-loop
  evidence, source-derived combat/retreat behavior, bounded `option_o`, one
  fixed provider action, signed presentation, fixtures, provenance, docs, and
  tests.
- Full external validation passed 106 Rust cases plus strict lint/docs,
  authenticated source/provenance checks, six trusted-control QML cases,
  seventeen signed screens, and provider-backed local play. The fixed
  fifteen-case TLS/replay/fault/callback corpus passed twice across provider
  restart, and the platform's complete twenty-four-stage diff gate passed.
- A fresh rules-v20 process replaced v19 and remains open on workspace 8 at a
  source-correct Level 15 Dark Hoodlum encounter with 60/60 HP. Real directed
  Tab/Return input advanced exactly one revision through entry, character
  creation, Main Street, Level 15 selection, and Look.
- The user's duplicate/inert-button report was not reproduced in provider plan
  data, the trusted-control regression, or fresh v20 action behavior. Revision
  5 had eighteen buttons with eighteen unique IDs/actions; revision 6 had five
  combat buttons with five unique IDs/actions. The compositor password overlay
  prevented an honest live pixel/mouse claim, so the workspace-8 window remains
  available for direct observation after unlock.
- Hand-maintained architecture and generated OpenWiki pages now describe rules
  v20, Level 15, boundary record 140, `option_o`, and the current 17-to-18
  delegate regression. OpenWiki returned `complete` with warnings for the two
  pages' pre-existing unresolved Claims evidence debt.

## Failures captured

- Inspection found one stale provenance-test reference left from v18. It was
  changed to the existing v20 schema/poison proof and the complete provenance
  document was re-read, parsed, hashed, and security-reviewed.
- The first platform gate attempt inherited a non-`/tmp` temporary directory,
  an ambient Cargo target directory, and a host PostgreSQL listener on the
  fixed port assumed by four existing drills. These are previously documented
  environment constraints rather than a new product failure. The host database
  was untouched; a ticket-scoped unexposed PostgreSQL instance, process-local
  port redirect, `/tmp`, and no ambient Cargo target allowed each failed suite
  and the complete gate to pass unchanged.
- The reported duplicate live buttons remain unconfirmed. Both v19 and v20
  plans were unique, real directed keyboard input worked, and the Qt suite
  passed actual pointer, enablement, single-emission, stale-removal, and
  17-to-18 delegate-cardinality checks; the desktop lock overlay prevented a
  safe compositor-level mouse click.

## Prevention rules captured

No new rule was needed. The stale provenance link was ordinary inspection
cleanup. The gate environment repeated the conditions already recorded by
Tickets 059, 065, and 067, and the existing Cargo-artifact and isolated-test
guidance remains sufficient. The one-phase-valid command, real-input, and
instantiated-delegate rules already cover the reported inert/duplicate-control
risk.

## Architecture decisions

No new ADR was required. ADR-0002's authority boundary held: the external
provider owns Usurper rules, state, RNG, and revisions, while OmarchyGS
authenticates and renders the inert plan. The only Ticket 069 platform source
change is game-neutral regression evidence; no production renderer, server,
database, migration, provider protocol, trusted node kind, or platform gameplay
rule changed.

## Effectiveness

Effective. Every recalled rule shaped a concrete source review, deterministic
test, signed action, or QML/live check. The generic band kept Level 15 narrow,
while the existing input and delegate invariants directly addressed the user's
report without a speculative production renderer change or a redundant new
prevention rule.
