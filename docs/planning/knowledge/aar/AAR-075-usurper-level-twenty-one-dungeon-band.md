## What happened

- Implemented the external v26 Level 21 slice with exact records 200–209,
  normal selection 201–209, strength 25/defence 12/75 HP encounters,
  draw-free switching across levels 1–21, bounded `option_u`, one fixed
  provider action, signed presentation, fixtures, provenance, compatibility
  documentation, and full deterministic/restart coverage.
- Ratcheted the trusted-QML surface from twenty-three to twenty-four controls.
  The signed plan and painted delegate rows were unique, but the live audit
  reproduced two accessibility-layer defects: native and manual press
  semantics were both exposed, and replacement controls could publish
  provisional bounds before a hidden workspace received layout.
- Corrected the game-neutral production surface with a native Qt Quick Controls
  button, no overlay mouse or manual accessibility press path, immediate old
  model invalidation, a generation-guarded empty event-loop turn, and delayed
  accessibility publication after layout/polish. The regression now observes
  retirement, twenty-four accessibility-ready non-overlapping delegates, and
  exactly one pointer and Return action per current button.
- External validation passed 142 Rust tests, clippy, rustdoc, authenticated
  provenance, six QML cases, seventeen signed screens, provider-backed local
  play, and the fifteen-case provider corpus twice across restart. Both
  external and platform Codex Security reviews completed with zero findings.
- A real compositor frame on workspace 8 exposed unique button rectangles, and
  one compositor-routed pointer click advanced exactly one provider revision.
  The final Level 21 screen was reviewed and the app, server, launcher, and
  temporary run directory were then closed and removed at the user's request.
- The post-documentation full platform gate passed all twenty-four stages. Its
  receipt, final gated state, CodeGraph inspection receipt, and OpenWiki
  completion receipt all match
  `06d97cc21082c889ba9006824c7dd51590069216d4ff7bf080e5c7ab879cd6f7`;
  all disposable network/database resources were removed while the host
  loopback PostgreSQL service remained healthy.

## Prevention rules captured

| ID | Rule | Why |
|---|---|---|
| `PR-omarchy-gaming-system-use-one-native-control-activation-path-001` | For a native QML control, use its native pointer, keyboard, and accessibility activation semantics; do not layer an overlapping mouse surface or manual accessibility press action over it. | Parallel activation paths can render once while exposing duplicate or multiply-dispatched assistive actions. |
| `PR-omarchy-gaming-system-retire-accessibility-before-plan-replacement-001` | On asynchronous trusted-plan replacement, expose an observable empty retirement turn, guard rematerialization by generation, and publish accessibility only after current layout/polish. | Stale accessibility objects and provisional geometry can survive across a visually correct replacement unless lifecycle retirement is explicit. |
| `PR-omarchy-gaming-system-probe-contained-clean-room-egress-before-gate-001` | Before a full gate in a network namespace, probe the exact DNS and outbound dependency path needed by clean-room builds and retain narrowly tagged, fully cleaned routing rules. | Database isolation alone does not prove package-resolution egress, and discovering that at late gate stages wastes a complete validation run. |

## Architecture decisions

No new ADR was required. ADR-0002's boundary held: the separate provider owns
Usurper data, rules, state, RNG, and revisions; OmarchyGS owns authenticated
lowering and trusted input/accessibility behavior. The QML correction is
game-neutral and changes no renderer protocol, gameplay authority, persistence,
registration, admission, deployment, or publication path.

## Effectiveness

Effective. Every recalled rule influenced source selection, rejected RNG work,
state sizing, provider transitions, or QML runtime evidence. Treating the
user's duplicate/inert report as release-blocking exposed defects below the
signed-plan layer that screenshots and delegate counts alone could not find.
The resulting native control path, explicit accessibility retirement/layout
lifecycle, twenty-four-control real-input regression, painted workspace audit,
full external corpus, security reviews, OpenWiki lifecycle, and matching
twenty-four-stage gate close the slice without committing, pushing, deploying,
admitting, or publishing it.
