## What happened

- Implemented external Usurper rules/state/cartridge v21 with exact Level 16
  records 150–159, draw-free levels 1–16 switching, source-order rejection
  evidence, source-derived combat/retreat behavior, bounded `option_p`, one
  fixed provider action, signed presentation, fixtures, provenance, docs, and
  tests.
- Full external validation passed 111 Rust tests plus strict lint/docs,
  authenticated source/provenance checks, six trusted-control QML cases,
  seventeen signed screens, and provider-backed local play. The corrected
  fixed fifteen-case TLS/replay/fault/callback corpus passed twice across a
  provider restart, and the platform's complete twenty-four-stage diff gate
  passed.
- A fresh rules-v21 process replaced v20 and remains open on workspace 8 at a
  source-correct Level 16 Red Spider encounter with 60/60 HP. Real directed
  Tab/Return input advanced exactly one revision through entry, character
  creation, Main Street, Level 16 selection, and Look.
- The user's duplicate/inert-button report was treated as an acceptance
  blocker. Live revision 5 had nineteen buttons with nineteen unique IDs and
  actions; revision 6 had five combat buttons with five unique IDs and
  actions. The Qt regression separately proved actual recursive delegate
  cardinality across an 18-to-19 replacement, stale removal, real pointer
  activation, enablement changes, and single Return emission.
- Hand architecture and generated OpenWiki pages now describe rules v21,
  Level 16, boundary record 150, `option_p`, and the current 18-to-19 delegate
  proof. No Claims sidecar was edited manually.

## Failures captured

- The first production conformance attempt returned HTTP 422. The Level 16
  deterministic retreat succeeded to the dungeon, but the fixed corpus had
  inherited a Level 15 death-only rewrite that changed the following valid
  Main Street action to `reenter`. The reducer and provider state were
  correct; the corpus was corrected to follow the observed phase, and its
  focused provider test now traverses cast, successful retreat, cleared
  monster, positive HP, and Main Street.
- This is recorded as
  `BF-omarchy-gaming-system-usurper-conformance-terminal-phase-drift-001`.
- The ticket-scoped test database and port redirect were required because the
  existing full gate assumes port 5432 while the host PostgreSQL listener was
  already occupied. The host service was neither stopped nor reused.

## Prevention rules captured

`PR-omarchy-gaming-system-lock-provider-corpus-to-tested-phase-transitions-001`:
whenever a fixed provider corpus changes a band-specific combat path, a
focused provider test must traverse the same next-phase sequence and assert
phase/state before the following corpus command is chosen.

## Architecture decisions

No new ADR was required. ADR-0002's authority boundary held: the external
provider owns Usurper rules, state, RNG, and revisions, while OmarchyGS
authenticates and renders the inert plan. `option_p` is a bounded external
view field; the only Ticket 070 platform source change is game-neutral
18-to-19 delegate regression evidence. No production renderer, server,
database, migration, Provider SDK, protocol, or platform gameplay rule
changed.

## Effectiveness

Effective. Every recalled rule shaped a concrete source review, deterministic
test, signed action, or QML/live check. The generic band kept Level 16 narrow,
the uniqueness and real-input proofs directly resolved the reported control
risk, and production conformance caught a validation-corpus assumption before
completion. The full external suite, provider restart corpus, security scan,
OpenWiki lifecycle, and platform gate all passed.
