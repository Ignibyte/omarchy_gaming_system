## What happened

- Implemented external Usurper rules/state/cartridge v19 with exact Level 14
  records 130–139, draw-free levels 1–14 switching, forced rejection-loop
  evidence, source-derived combat/retreat behavior, bounded `option_n`, one
  fixed provider action, signed presentation, fixtures, provenance, docs, and
  tests.
- Full external tests passed 101 Rust cases plus strict lint/docs, provenance,
  six real-input QML cases, seventeen signed screens, and provider-backed local
  HTTP/QML smoke. The fixed fifteen-case TLS/replay/fault/callback corpus passed
  twice across provider restart, and the platform's complete 24-stage diff gate
  passed.
- A fresh rules-v19 process replaced the old preview and remains open on
  workspace 8. Real Tab/Return input advanced exactly one revision through
  character creation, Main Street, Level 14 selection, and Look; the resulting
  encounter is a source-correct Level 14 Wood Elf at 60/60 HP.
- The user's duplicate-button report was not reproduced in plan data, the
  isolated exact-plan render, recursive delegate counts, or fresh v19 action
  behavior. The compositor screenshot was obscured by the desktop password
  overlay, so the new workspace-8 window remains available for direct visual
  confirmation after unlock rather than treating the report as disproven.
- Hand-maintained architecture and generated OpenWiki pages now describe rules
  v19, Level 14, boundary record 130, `option_n`, and the current 16-to-17
  delegate regression. OpenWiki returned `complete` with warnings for the two
  pages' pre-existing unresolved Claims evidence debt.

## Failures captured

- The first signed-cartridge run failed because the new Level 14 Button
  referenced `enter_dungeon_level_14` before that exact empty-payload action was
  added to the presentation action registry. The missing declaration was added;
  focused conformance and the full external suite then passed without weakening
  validation.
- An initial direct QML test-runner lookup exited before running tests. The
  canonical Qt installation path was used instead, and all six cases passed.
- The reported duplicate live buttons remain unconfirmed. One mapped window,
  unique live plan data, an isolated exact-plan capture, recursive actual-node
  counts, and one-revision-per-key live behavior were all clean; the desktop
  lock overlay prevented an honest post-fix compositor-pixel claim.

## Prevention rules captured

No new rule was needed. The existing one-phase-valid command rule caught the
missing action declaration, and the existing real-input plus instantiated-node
rules already state the required prevention for inert, stale, or duplicate QML
controls.

## Architecture decisions

No new ADR was required. ADR-0002's boundary held: the separate provider owns
Usurper rules, state, RNG, and revisions, while OmarchyGS authenticates and
renders the inert plan. The only Ticket 068 platform implementation change is
game-neutral regression evidence; no server route, migration, provider
protocol, trusted node kind, or platform gameplay rule changed.

## Effectiveness

Effective. Every recalled rule shaped a concrete source review, deterministic
test, signed action, or QML/live check. Reusing the generic band kept the slice
small, while strict signed-presentation validation found the only substantive
implementation defect before completion. No duplicate prevention rule was
added merely to restate existing durable guidance.
