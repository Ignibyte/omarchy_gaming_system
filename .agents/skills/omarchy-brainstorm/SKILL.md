# Omarchy brainstorm

Read the product charter, roadmap, knowledge register, and relevant architecture
documents. Inspect code only when it informs feasibility.

Separate the user problem and desired experience, viable approaches and
tradeoffs, risks and unknowns, and the smallest shippable slice. Ask only about
choices that materially change the outcome.

If the idea is useful but not ready for implementation, capture it from
`docs/planning/_templates/intake.md` when the user wants it persisted. If it is
ready and the user authorizes implementation, hand off to `$omarchy-workflow`.
Do not silently open a ticket or write application code.
